# Server TypeScript migration (Phase 3)

Goal: convert every first-party .js file under server/ and index.js to TypeScript, one batch (directory) at a time. The vendored code in server/libs and all files under test/ stay as they are.

## Rules (apply to every batch)
1. At the end of every batch `npm run build:server` must report 0 "error TS" and `npm test` must show 356 passing, 0 failing. Never end a session with a red build.
2. Do not edit, skip or delete any test. Do not change files outside the batch unless a type error in the batch cannot be fixed otherwise; list any such change in the Log below.
3. Runtime behaviour must not change. Do not fix bugs. When types expose a bug, keep the behaviour, add a `NOTE:` comment at that line and add one line to the Bugs section below.
4. No `any`, no `@ts-ignore`, no `@ts-nocheck`, no `@ts-expect-error`. Use `unknown` and narrow it. Every type assertion (`as`) needs a one-line comment.
5. Module style (copied from Phase 1 and 2): local modules use `import X = require('./X')` and `export = X`, so existing require() callers, tests and sinon stubs keep working. Third-party packages with a default export use `import x from 'pkg'`.
6. Shared types live next to the data they describe (see server/providers/types.ts). Add a types.ts in the directory when two or more files share a type.
7. Convert with `git mv X.js X.ts` so history is kept. Keep JSDoc descriptions and drop JSDoc type annotations that the signature now carries.
8. At the end of each batch: update the Progress table, commit with the message `phase3 batch N: <directory>`, and stop.

## Bugs found (not fixed)
Each has a `NOTE:` comment at the line.
- server/utils/generators/opmlGenerator.ts: reads `podcast.itunesPageUrl` but the Podcast model field is `itunesPageURL`, so the OPML outline never gets an `htmlUrl`.
- server/utils/podcastUtils.ts `extractImage`: xml2js puts `<image>` in an array, so `channel.image.url` is always undefined and the RSS `<image><url>` is never used (always falls back to `itunes:image`).
- server/utils/podcastUtils.ts `extractEpisodeData`: the second `media:content` find does not require a url, so an audio `media:content` without a url makes `enclosure.url.trim()` throw.
- server/utils/scandir.ts `groupFileItemsIntoLibraryItemDirs`: a media file in the folder root is stored as a string group; if a directory has the same name, `.push` is called on that string and throws (2 places).
- server/utils/parsers/parseFullName.ts: `fixCase !== 'undefined'` compares with the string 'undefined' instead of using typeof, so that part of the check is always true.
- server/utils/parsers/parseFullName.ts `fixParsedNameCase`: the suffix check indexes `namePartLabels[j]` (word index) instead of `namePartLabels[i]` (label index).
- server/utils/comicBookExtractors.ts `CbzComicBookExtractor.open`: `getBuffer()` can return null, which is passed to `Archive.open` unchecked (the class is not used by `createComicBookExtractor` at the moment).
- server/utils/migrations/dbMigration.ts `handleOldLibraries`: maps `oldDbIdMap.libraries[library.oldLibraryId]`, but the Library model has no `oldLibraryId` (it was just written to `extraData`), so the key is "undefined" and old library ids in users' `librariesAccessible` are mapped to undefined and dropped.
- server/objects/files/LibraryFile.ts `setDataFromPath`: `getFileTimestampsWithIno` returns `false` when stat fails; the file is then created with `ino` undefined and no size/timestamps, and no error is reported.
- server/auth/TokenManager.ts `rotateTokensForSession`: when the conditional update hits 0 rows and the session row has been deleted in the meantime, `findOne` returns null and `updatedSession.refreshToken` throws.
- server/auth/OidcAuthStrategy.ts `verifyCallback`: when no user matches and auto-register is off, `user.isActive` is read on null and throws a TypeError, so the intended 'User not active or not found' error is never thrown (the login still fails, the log shows the TypeError).
- server/routers/ApiRouter.ts `getUserListeningStatsHelpers`: reads `s.lastUpdate`, but PlaybackSession has no `lastUpdate` (it is `updatedAt`), so `items[id].lastUpdate` is always undefined.
- server/models/Collection.ts `getOldCollectionsJsonExpanded`: the permission-filtered books are assigned to `this.books`, which in this static method is the Collection class, not the collection `c`; `c.toOldJSONExpanded()` then uses the unfiltered `c.books`, so users with tag or explicit-content restrictions get every book of a collection they can see (and the class gets a stray `books` property).
- server/models/Library.ts `getMaxDisplayOrder`: `this.max('displayOrder') || 0` applies `|| 0` to the promise, which is always truthy, so with no libraries it resolves to null instead of 0.
- server/models/Author.ts `getAllLibraryItemsForAuthor`: `author.books` is read without checking that `findByPk` found the author, so an unknown author id throws a TypeError.
- server/models/Feed.ts `updateFeedForEntity`: when the library item, collection or series of the feed no longer exists, `getExpandedById` returns null and `getFeedObjFor...` throws a TypeError before the try block (3 places), so the caller gets an exception instead of null.
- server/models/Playlist.ts `checkHasMediaItem`: without an episodeId it reads `pmi.mediaItem.libraryItem.id` for every item, but a podcast episode media item has no `libraryItem` (it is on `episode.podcast`), so it throws a TypeError for playlists that contain episodes.
- server/models/PodcastEpisode.ts `createFromRssPodcastEpisode`: RSS chapters can have `end: null` (the RSS parser types them so), and they are stored in the `chapters` column, which everything else reads as chapters with a numeric end.
- server/models/LibraryItem.ts `saveMetadataFile`: the podcast branch writes `asin: mediaExpanded.asin`, but Podcast has no asin, so it is always undefined (and left out of metadata.json).
- server/models/User.ts `checkCanAccessLibraryItem`: `libraryItem.media.metadata?.explicit` reads a property of the old models; Book and Podcast have no `metadata`, so that half of the explicit check is always false.
- server/models/Session.ts `refreshToken` (with server/auth/TokenManager.ts `createTokensAndSession`, `rotateTokensForSession`): the column is NOT NULL, but TokenManager writes `generateRefreshToken` results, which are null when signing fails; the create/update then fails validation and throws instead of reporting the signing error.
- server/managers/NotificationManager.ts `onTest`: calls `triggerNotification('onTest')` without event data; `getApprisePayload` then reads the template variables from undefined and throws a TypeError for the default onTest templates (`{{version}}`). onTest is not called anywhere at the moment.
- server/managers/CronManager.ts `checkUpdatePodcastCron`: the log title falls back to `libraryItem.media.metadata?.title`, an old-model property; Podcast has no `metadata`, so the fallback is always undefined.
- server/managers/RssFeedManager.ts `checkFeedRequiresUpdate`: when the library item, collection or series of a feed no longer exists, `getEntity` returns null and the next read throws a TypeError (2 places); `getFeed`: when `updateFeedForEntity` returns null, `feed.buildXml` throws a TypeError.
- server/managers/PodcastManager.ts `createPodcastsFromFeedUrls`: when `getFileTimestampsWithIno` fails (returns false), the library item is created with `ino` undefined and the timestamps 0; when the feed title is empty or not a string, `sanitizeFilename` returns false, so the podcast path ends in "/false" and `relPath` is false.
- server/managers/CoverSearchManager.ts `startSearch`: on a failed search it calls `onError(error.message)`, but onError takes (provider, errorMessage), so the client gets the message as the provider and an undefined error.
- server/managers/MigrationManager.ts constructor: the default `configPath = global.configPath` reads a global that is never set (the global is `ConfigPath`); Database passes the path, so the default is not used.
- server/scanner/MediaProbeData.ts `setData`: prober accepts a file with only a video stream; `audio_stream` is then null and the reads of `this.audioStream` throw a TypeError, which prober.probe returns as the error (so the AudioFileScanner "no audio stream" message is not used for such files).
- server/scanner/AudioFileScanner.ts `getTrackAndDiscNumberFromFilename`: reads `author` and `series` from the filename metadata, which has `authors` and `seriesName`, so the author and series are never removed from the filename; `partbasename.replace(publishedYear)` has no replacement, so the year is replaced with the string "undefined".
- server/scanner/PodcastScanner.ts `saveMetadataFile`: writes `asin: libraryItem.media.asin`, but Podcast has no asin, so it is always undefined (same as LibraryItem `saveMetadataFile`).
- server/scanner/LibraryItemScanner.ts `getLibraryItemScanData`: when `getFileTimestampsWithIno` fails (returns false), the scan data gets `ino` undefined and the timestamps 0.
- server/scanner/Scanner.ts `quickMatchLibraryItem`: `PodcastFinder.search` returns null for a podcast without a title, and `results.length` then throws a TypeError.
- server/scanner/LibraryScanner.ts `scanLibrary`: when a library item is removed while the scan runs, `getExpandedById` returns null and the null is pushed to the updated items and emitted to clients (`items_updated`).

14. Tag every new cast with its reason. Write `// cast(a): <why>` directly above the cast, where the letter is one of:
    - a: untyped or vendored library
    - b: Sequelize or Express typing limitation
    - c: a real mismatch in the original JavaScript. A cast tagged c must also have a NOTE comment and an entry under Bugs.
    - d: other
    This replaces the plain one-line comment for new casts. Existing casts are not retagged now.

15. Banned shortcuts. Do not use:
    - index signatures on domain types (allowed only for real dictionaries)
    - function types with `never` parameters
    - `null as unknown as T`. If the JavaScript assigns null or checks for null, declare the field `T | null` and handle null where it is used, without changing behaviour. If the JavaScript never initialised the field, use `declare x: T` (rule 12).
    - casting req.query or req.body to all-string shapes. Use `string | string[] | undefined`, or a small narrowing helper that keeps the same behaviour.
    If a file cannot be done without one of these, leave it as .js and list it under Skipped files with the reason.

16. Narrow with type guards, not with `as`. A parameter type must not be wider than the JSDoc it replaces (for example, no `unknown` where the JSDoc said `boolean`).
